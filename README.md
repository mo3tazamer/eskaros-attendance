# بوابة الموظفين — تطبيق الحضور وطلبات السلف

تطبيق ويب للموبايل يسجّل حضور الموظفين ويستقبل طلبات السلف، ويتكامل مباشرة مع
برنامج الرواتب الحالي. كل موظف له حساب خاص، وكل طلب سلفة يوافق عليه المدير
يُسجَّل تلقائيًا في «السلف» داخل برنامج الرواتب.

- واجهة عربية كاملة (RTL) مصممة للموبايل.
- يعمل على شبكة الشركة المحلية من أي هاتف متصل بالواي فاي.
- يعمل **محليًا بملفات JSON** بدون إنترنت، أو **على Supabase Postgres** عند ضبط `DATABASE_URL`.
- بيانات الحضور والسلف والموظفين مشتركة مع برنامج الرواتب في نفس التخزين.

---

## المتطلبات

- Windows (تم اختباره على Windows 10/11).
- [Node.js](https://nodejs.org) الإصدار **20 أو أحدث** (نسخة LTS).
- لا حاجة لتثبيت أي حزم إضافية (`npm install` غير مطلوب).

---

## التشغيل السريع

1. تأكد من تثبيت Node.js:
   ```
   node -v
   ```
2. شغّل الملف:
   ```
   start.bat
   ```
3. افتح المتصفح على:
   ```
   http://localhost:3000
   ```
4. في أول تشغيل تظهر شاشة **إنشاء حساب المدير**. أدخل اسم المستخدم وكلمة المرور
   (6 أحرف على الأقل) ثم تابع.

أول تشغيل فقط:

- **استورد بيانات الرواتب** حتى تظهر أسماء الموظفين:
  سجّل الدخول كمدير ← الإعدادات ← «فتح برنامج الرواتب» ← من داخل البرنامج:
  **ملف البيانات ← استيراد نسخة احتياطية** واختر أحدث نسخة احتياطية لديك.
- ارجع إلى تطبيق الحضور ← **حسابات الموظفين** ← اضغط على الموظف ← أنشئ له
  اسم مستخدم وكلمة مرور وسلّمها له.

> نصيحة: خذ نسخة احتياطية من برنامج الرواتب قبل الاستيراد الأول.

## الدخول من الهواتف (شبكة الشركة)

الخادم يعمل على جميع واجهات الشبكة. بعد تشغيل `start.bat` ستظهر في نافذة الأوامر
عناوين مثل:

```
على هذا الجهاز:  http://localhost:3000
على الشبكة:      http://192.168.1.19:3000
```

افتح عنوان الشبكة من متصفح الهاتف (يجب أن يكون الهاتف على نفس شبكة الواي فاي).

إذا لم يفتح الرابط من الهاتف:

1. اسمح لـ Node.js بالاتصال في **Windows Firewall** (اختر «شبكات خاصة»).
2. تأكد أن الهاتف والكمبيوتر على نفس الشبكة وليس على شبكة الضيوف.
3. تأكد أن عنوان الكمبيوتر لم يتغيّر؛ يمكن تثبيته من إعدادات الراوتر.

> التطبيق يعمل على الشبكة المحلية عبر HTTP. ميزة «التثبيت على الشاشة الرئيسية»
> تعمل على `localhost` أو عبر HTTPS فقط؛ الاستخدام العادي من المتصفح يعمل دائمًا.

## النشر السحابي + APK

### التخزين: JSON محلي أو Supabase Postgres

- بدون `DATABASE_URL`: ملفات JSON محلية (الوضع الافتراضي، مجاني تمامًا).
- مع `DATABASE_URL`: كل البيانات في Postgres — مثالي للنشر السحابي حيث
  **قرص الاستضافة مؤقت**، فلا حاجة لقرص دائم مدفوع.
- المبدّل الوحيد هو `DATABASE_URL`؛ كل الخدمات (حضور، سلف، حسابات، رواتب)
  تستخدم نفس الواجهة، فلا يتغيّر أي شيء في الواجهة أو الـ APK.

### إنشاء Supabase وتوصيله (حوالي 10 دقائق)

1. أنشئ مشروعًا جديدًا في [Supabase](https://supabase.com) (خطة مجانية —
   500MB، كافية لهذا التطبيق).
2. انسخ **Session connection string** (المنفذ 5432 مع `?sslmode=require`)
   من: Project Settings ← Database ← Connection string.
3. على جهازك:
   ```bat
   set DATABASE_URL=postgresql://postgres.<ref>:<password>@db.<ref>.supabase.co:5432/postgres?sslmode=require
   npm install
   npm run db:migrate
   node server\index.js
   ```
   - `npm run db:migrate` ينسخ بياناتك المحلية (data/*.json) إلى Supabase.
   - بعد أول تشغيل ناجح، لا حاجة لـ `db:migrate` مرة أخرى.
4. على Render: أضف متغير البيئة `DATABASE_URL` بنفس القيمة
   (Render ← Service ← Environment). ثم أعد النشر.
5. جرّب `/healthz` — يجب أن يعرض `ok`.

> **ملاحظة مهمة:** إن نزّلت نسخة احتياطية من التطبيق قديمًا، استوردها من
> داخل `/payroll/` فقط للبيانات الحالية — البيانات في Postgres هي المرجع
> بعد التشغيل بهذا الرابط.

### النشر على Render (الأسهل)

1. ارفع المجلد إلى GitHub (بما فيه `package-lock.json` الجديد).
2. في [Render](https://render.com) ← **New Web Service** ← اختار المستودع.
   الملف `render.yaml` و `Dockerfile` جاهزان (مع `npm install --omit=dev`).
3. بعد النشر: انسخ رابط HTTPS (مثال: `https://eskaros-attendance.onrender.com`).
4. أنشئ حساب المدير، استورد بيانات الرواتب من داخل `/payroll/`، ثم أنشئ
   حسابات الموظفين.
5. جرّب `/healthz` في المتصفح — يجب أن يعرض `ok`.

ملاحظة عن الحدود المجانية في Render:

- تنام البلد الراجع في Render مجانًا بعد **15 دقيقة** من عدم النشاط
  (أول طلب بعد النوم قد يستغرق ~30 ثانية). لا يؤثر على البيانات مع Postgres.
- مجلّد `backups/` يُكتب محليًا فقط ويختفي عند إعادة التشغيل في الخطط المجانية.
  النسخ الاحتياطية الحقيقية هي في Supabase (Dashboard ← Database ← Backups).

### بناء الـ APK (نفس الواجهة)

### بناء الـ APK

هيكل الـ APK جاهز في مجلد `mobile/` (Capacitor يفتح رابط السيرفر).
راجع `mobile/README.md` — خطوات كاملة للمحترف (Android Studio) وبدون
Android Studio (PWABuilder). يمكنك أيضًا تثبيت التطبيق مباشرة من Chrome:
قائمة ⋮ ← «تثبيت التطبيق» — بدون أي ملف APK.

### ملاحظة مهمة عن الخصوصية على الإنترنت

عند النشر العام: الرواتب (`/payroll/`) محمية بكلمة مرور المدير، لكن
**غيّر كلمة المرور الافتراضية**، لا تشارك روابط النسخ الاحتياطية، وتنزّل
نسخة احتياطية دورية من الإعدادات.

## استخدام الموظف

- **تسجيل الحضور:** يفتح الرئيسية ويضغط «تسجيل الحضور». يُحسب التأخير تلقائيًا
  بعد دقائق السماح المحددة في الإعدادات.
- **سجل الحضور:** يعرض أيام الشهر وحالاتها (حضور / غياب / إجازة / نص يوم).
- **طلبات السلف:** يقدّم طلبًا بمبلغ وسبب، إما **فوري** أو **مجدول**، ويتابع حالته
  (قيد المراجعة / موافَق عليه / مرفوض / ملغى) ويمكنه الإلغاء قبل المراجعة.
- **الملف الشخصي:** بياناته وكلمة المرور.

## استخدام المدير

- **الرئيسية:** ملخص اليوم وعدد الطلبات المعلّقة.
- **الحضور:** مراجعة حضور اليوم وتعديل حالة أي موظف عند الحاجة.
- **طلبات السلف:** الموافقة أو الرفض. عند الموافقة يُنشأ مستند سلفة متوافق مع
  برنامج الرواتب تلقائيًا.
- **حسابات الموظفين:** إنشاء الحسابات، تغيير كلمات المرور، تعطيل/تفعيل الحساب.
- **الإعدادات:** اسم التطبيق، مواعيد العمل، دقائق السماح، العملة، المنطقة الزمنية،
  تغيير كلمة مرور المدير، تنزيل نسخة احتياطية، وفتح برنامج الرواتب.

كلمة مرور المدير تُزامَن تلقائيًا مع حساب المدير داخل برنامج الرواتب، لذا يكفي
تسجيل دخول واحد لفتح البرنامجين.

## العلاقة ببرنامج الرواتب

- برنامج الرواتب الأصلي يُقدَّم كما هو على المسار `/payroll/` (للمدير فقط).
- التطبيق يوفّر نفس واجهة `api/*` التي يتوقعها البرنامج، لذا يقرأ ويكتب في نفس
  المجموعات: `employees`، `attendance`، `advances`، `settings`، `users`…
- الحضور المسجَّل من الهاتف يظهر مباشرة في برنامج الرواتب.
- السلفة الموافق عليها تُسجَّل في «السلف» بنوع «فوري» أو «مجدولة».
- يمكنك متابعة العمل داخل برنامج الرواتب كالمعتاد؛ أي تعديل على الموظفين يظهر
  في التطبيق.

### النسخ الاحتياطي

- نسخة تلقائية كل 6 ساعات داخل مجلد `backups/` (يُحتفظ بآخر 14 نسخة).
- نسخة يدوية فورية من: الإعدادات ← **تنزيل نسخة احتياطية**.
- لاستعادة البيانات: استخدم استيراد النسخة الاحتياطية داخل برنامج الرواتب.
- **مهم:** أوقف الخادم قبل نسخ مجلد `data/` يدويًا لتجنب نسخ ملفات أثناء الكتابة.

## الإعدادات المتقدمة (اختياري)

يمكن ضبط القيم عبر متغيرات البيئة قبل التشغيل:

| المتغير | الافتراضي | الوصف |
| --- | --- | --- |
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `0.0.0.0` | واجهة الاستماع (اتركه للشبكة المحلية) |
| `DATA_DIR` | `./data` | مكان ملفات البيانات (JSON وضع فقط) |
| `BACKUP_DIR` | `./backups` | مكان النسخ الاحتياطية |
| `SESSION_TTL_MS` | 30 يومًا | مدة بقاء تسجيل الدخول |
| `DATABASE_URL` | *(فارغ = JSON)* | رابط Postgres (Supabase) |

مثال على Windows:

```bat
set PORT=8080
node server\index.js
```

## حل المشكلات

| المشكلة | الحل |
| --- | --- |
| `المنفذ 3000 مستخدم بالفعل` | أغلق النسخة الأخرى أو شغّل بـ `set PORT=3001` |
| شاشة بيضاء بعد تحديث الواجهة | حدّث الصفحة بقوة (`Ctrl+F5`) أو امسح بيانات الموقع |
| الموظفون لا يظهرون | استورد نسخة بيانات الرواتب من داخل `/payroll/` |
| الهاتف لا يفتح الرابط | راجع Windows Firewall وتأكد من نفس الشبكة |
| نسيت كلمة مرور المدير | أوقف الخادم واحذف `data/accounts.json` و`data/users.json` ثم أعد التشغيل لإعداد المدير من جديد (تبقى بقية البيانات) |
| توقيت التأخير غير صحيح | اختر المنطقة الزمنية الصحيحة من الإعدادات |

## الخصوصية

كل البيانات محفوظة محليًا على خادمك، ولا يُرسل أي شيء إلى الإنترنت. الجلسات
محمية بكوكيز `HttpOnly`، وكلمات المرور مخزّنة بتشفير `scrypt`، مع قفل مؤقت بعد
5 محاولات دخول فاشلة.
